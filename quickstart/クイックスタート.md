## 3. ステップ 1: まずは 30 秒でサンプルサーバーを動かしてみる

まずはリポジトリに入っているサンプルサーバー（`samples/Hayabusa.SampleServer`）をそのまま起動して、Web エンドポイントが応答することを確認しましょう。

### 1-1. .NET CLI で起動して確認する

**ターミナル 1（サーバー起動用）** を開き、リポジトリのルートディレクトリで以下を実行します。

```bash
dotnet run --project samples/Hayabusa.SampleServer -c Release -- --http-port 8000 --rpc-port 8001
```

続いて、**ターミナル 2（動作確認用）** を開き、`curl` コマンドで HTTP リクエストを送ってみましょう。

```bash
# 1. ヘルスチェックエンドポイントの確認
curl -i http://localhost:8000/health
```

以下のように `200 OK` と `OK` が返ってくれば成功です。

```http
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Server: Hayabusa
Access-Control-Allow-Origin: *
Content-Length: 2

OK
```

JSON エンドポイントも叩いてみましょう。

```bash
# 2. JSON ステータス API の確認
curl -i http://localhost:8000/api/status
```

```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Server: Hayabusa
Access-Control-Allow-Origin: *
Content-Length: 32

{"status":"ok","engine":"Hayabusa"}
```

確認が終わったら、ターミナル 1 で `Ctrl + C` を押すとサーバーが安全に停止（グレースフルシャットダウン）します。

### 1-2. Docker Compose で 1 コマンド起動する（.NET SDK 不要）

Docker 環境がある場合は、以下のコマンドだけで Linux `io_uring` 最適化済みのコンテナをビルドして起動できます。

```bash
# 1. 設定ファイル (.env) をサンプルから作成（HTTP: 8000, RPC: 8001）
cp .env.example .env

# 2. バックグラウンドでビルド＆起動
docker compose up -d --build

# 3. 動作確認
curl -i http://localhost:8000/health
curl -i http://localhost:8000/api/status

# 4. 停止する場合
docker compose down
```

### 1-3. VS Code / Cursor の DevContainer で開発環境を開く

手元の PC を汚さずに `.NET 9 SDK` + `clang` (NativeAOT) + `liburing-dev` がすべて揃った環境で開発したい場合は、本リポジトリを **Cursor** または **VS Code** で開き、コマンドパレット（`Ctrl+Shift+P` / `Cmd+Shift+P`）から **`Dev Containers: Reopen in Container`** を選択してください。自動的に開発用コンテナが立ち上がります。

## 4. ステップ 2: ゼロから新規プロジェクトを作成する

ここからは、あなた自身の新しいサーバープロジェクト（例: `MyHayabusaServer`）をゼロから作成する方法を解説します。**方法 A（テンプレート利用）** と **方法 B（手動構成）** のどちらか好きな方を選んでください。

### 方法 A: `dotnet new` テンプレートから 1 コマンドで作成する（推奨）

本リポジトリには、`dotnet new` でプロジェクトの雛形を一発生成できるテンプレートが同梱されています。

```bash
# 1. リポジトリルートでテンプレートをインストール（初回のみ）
dotnet new install ./templates/Hayabusa.Templates

# 2. 好きなフォルダで新規プロジェクトを作成
dotnet new hayabusa-server -n MyHayabusaServer

# 3. 作成したフォルダへ移動
cd MyHayabusaServer
```

これだけで、必要な設定と最小のサンプルコードが入った `MyHayabusaServer.csproj` と `Program.cs` が生成されます。

### 方法 B: 空のコンソールアプリから手動で `.csproj` を構成する

既存ソリューション内や手動で 1 からプロジェクトを作りたい場合は、以下のように `.csproj` を作成します。

#### リポジトリ内で参照する場合の `MyHayabusaServer.csproj`

Source Generator（`Hayabusa.Generator`）を動作させるため、`Hayabusa.Generator.csproj` には **`OutputItemType="Analyzer" ReferenceOutputAssembly="false"`** を付与するのがポイントです。

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net9.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>disable</ImplicitUsings>
    <IsAotCompatible>true</IsAotCompatible>
  </PropertyGroup>

  <ItemGroup>
    <!-- Hayabusa コアライブラリ群 -->
    <ProjectReference Include="..\src\Hayabusa.Core\Hayabusa.Core.csproj" />
    <ProjectReference Include="..\src\Hayabusa.Rpc\Hayabusa.Rpc.csproj" />
    <ProjectReference Include="..\src\Hayabusa.Transport\Hayabusa.Transport.csproj" />
    <ProjectReference Include="..\src\Hayabusa.Runtime\Hayabusa.Runtime.csproj" />

    <!-- Hayabusa Source Generator (コンパイル時コード生成用) -->
    <ProjectReference Include="..\src\Hayabusa.Generator\Hayabusa.Generator.csproj"
                      OutputItemType="Analyzer"
                      ReferenceOutputAssembly="false" />
  </ItemGroup>

  <ItemGroup>
    <!-- Cysharp OSS パッケージ -->
    <PackageReference Include="MemoryPack" />
    <PackageReference Include="ZString" />
    <PackageReference Include="ZLogger" />
    <PackageReference Include="R3" />
    <PackageReference Include="UniTask" />
  </ItemGroup>

</Project>
```

## 5. ステップ 3: 【Web サーバー編】高速 HTTP / REST API サーバーを実装する

まずはゲーム機能を使わず、**純粋な高速 Web / HTTP API サーバー**として実装する方法を見ていきましょう。

### 3-1. Minimal API スタイルでエンドポイントを実装する

ASP.NET Core の Minimal API を触ったことがある方なら、ほぼ同じ感覚で書けます。
`Program.cs` を以下の内容に書き換えてください。

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;
using Hayabusa.Runtime.Hosting;

namespace MyHayabusaServer;

public static class Program
{
    public static async Task Main(string[] args)
    {
        // 1. Web サーバー専用モード (HTTP ポート 8000) でサーバーを構築
        //    UseWebServerOnly() を呼ぶと、ゲーム用の Tick ループが停止し、
        //    全ワーカースレッドが 100% HTTP リクエスト処理に専念します。
        using HayabusaApp app = HayabusaApp.CreateBuilder(args)
            .UseWebServerOnly(httpPort: 8000)
            .Build();

        // 2. GET /health : 固定 UTF-8 文字列をゼロアロケーションで返す
        app.MapGet("/health", static ctx => ctx.WriteUtf8("OK"u8));

        // 3. GET /api/status : JSON をゼロアロケーションで返す
        app.MapGet("/api/status", static ctx =>
            ctx.WriteJsonUtf8("""{"status":"ok","server":"Hayabusa"}"""u8));

        // 4. GET /api/worker : 動的な数値 (担当した CPU コア番号) を ZString で文字列化せず直接書き込む
        app.MapGet("/api/worker", static ctx =>
            ctx.WriteZString("Handled by Worker Core #{0}", ctx.CoreIndex.Value));

        // 5. POST /api/echo : POST リクエストを受け取る
        app.MapPost("/api/echo", static ctx =>
            ctx.WriteJsonUtf8("""{"received":true}"""u8));

        // 6. Ctrl + C で安全に終了できるように設定してサーバーを起動
        using var cts = new CancellationTokenSource();
        Console.CancelKeyPress += (_, e) =>
        {
            e.Cancel = true;
            cts.Cancel();
        };

        Console.WriteLine("Hayabusa Web Server listening on http://localhost:8000");
        await app.RunAsync(cts.Token);
    }
}
```

#### コードの解説
- **`"OK"u8` とは？**:
  C# 11 以降の「UTF-8 文字列リテラル」です。通常の `string`（UTF-16）を作ってから変換するのではなく、コンパイル時に最初から UTF-8 のバイト列（`ReadOnlySpan<byte>`）として埋め込まれるため、**メモリ割り当て（GC アロケーション）が完全に 0 バイト**になります。
- **`static ctx => ...` とは？**:
  ラムダ式に `static` を付けることで、外部変数の意図しないキャプチャ（クロージャ生成によるヒープアロケーション）をコンパイラレベルで防止しています。

### 3-2. 4種類のゼロアロケーション HTTP レスポンス出力 API

ハンドラの引数 `ctx`（`HayabusaContext`）には、用途に合わせて以下の4つの書き込みメソッドが用意されています。

| メソッド | 返却される `Content-Type` | 使いどころ | 記述例 |
| --- | --- | --- | --- |
| `ctx.WriteUtf8(...)` | `text/plain; charset=utf-8` | プレーンテキストを返すとき | `ctx.WriteUtf8("Hello World"u8);` |
| `ctx.WriteJsonUtf8(...)` | `application/json; charset=utf-8` | JSON レスポンスを返すとき | `ctx.WriteJsonUtf8("""{"id":1}"""u8);` |
| `ctx.WriteZString(format, arg)` | `text/plain; charset=utf-8` | 変数や数値を埋め込んだテキストをアロケーション 0B で返すとき | `ctx.WriteZString("Tick: {0}", ctx.CurrentTick.Value);` |
| `ctx.WriteMemoryPack(...)` | `application/x-memorypack` | バイナリシリアライズ済みデータを HTTP 経由で返すとき | `ctx.WriteMemoryPack(binarySpan);` |

### 3-3. Source Generator 属性ルーティング（`[HayabusaService]`）で実装する

エンドポイントが増えてきたら、クラスに分けて `[HayabusaService]` と `[Get]` / `[Post]` 属性で整理できます。
リフレクションは一切使われず、コンパイル時に Source Generator が高速なルーティングコードを自動生成します。

```csharp
using Hayabusa.Rpc;

namespace MyHayabusaServer;

// ★重要: Source Generator がコードを追加するため、必ず「partial」を付けてください
[HayabusaService]
public sealed partial class UserWebService
{
    // GET /users/health
    [Get("/users/health")]
    public void GetHealth()
    {
        // メソッドが正常終了すると自動的に HTTP 200 OK ("OK") が返されます
    }

    // GET /users/{id}
    // URL 内の {id} は Utf8Parser によってアロケーション 0B で int に自動変換されます！
    // (int, uint, long, ulong, Guid, ReadOnlySpan<byte>, string に対応)
    [Get("/users/{id}")]
    public void GetUserById(int id)
    {
        // 取得した id を使った処理
        _ = id;
    }

    // POST /users/create
    [Post("/users/create")]
    public void CreateUser()
    {
        // POST 処理
    }
}
```

作成したサービスクラスは、`Program.cs` で **`app.MapService<UserWebService>()`** を 1 行呼ぶだけで登録完了です。

```csharp
using HayabusaApp app = HayabusaApp.CreateBuilder(args)
    .UseWebServerOnly(httpPort: 8000)
    .Build();

// Source Generator で生成された Web サービスを登録
app.MapService<UserWebService>();

await app.RunAsync();
```

### 3-4. ブラウザ連携（CORS 自動応答）を確認する

React / Vue / Blazor WebAssembly などのブラウザアプリから API を呼ぶ際、ブラウザは事前に `OPTIONS` リクエスト（CORS プリフライト）を送信します。
`Hayabusa` はこれに対して**追加コード 0 行で自動的に `204 No Content` と CORS 許可ヘッダーを返します**。

```bash
curl -i -X OPTIONS http://localhost:8000/api/status
# => HTTP/1.1 204 No Content (Access-Control-Allow-Origin: * 等が自動付与される)
```

## 6. ステップ 4: 【RPC 編】MemoryPack バイナリ RPC サーバー & クライアントを実装する

次に、JSON よりも圧倒的に高速で型安全な **Cysharp `MemoryPack` を使ったバイナリ RPC（Remote Procedure Call：遠隔メソッド呼び出し）** を実装してみましょう。

### 4-1. 通信データ型（DTO）を `[MemoryPackable]` で定義する

リクエストやレスポンスでやり取りするデータ構造体には、`[MemoryPackable]` 属性と `readonly partial record struct` を付けます。

```csharp
using Hayabusa.Core.Primitives;
using MemoryPack;

namespace MyHayabusaServer;

// プレイヤーの移動コマンド (クライアント → サーバー)
// ★重要: MemoryPack がシリアライズコードを自動生成するため「partial」が必須です
[MemoryPackable]
public readonly partial record struct MoveCommand(float X, float Y, float Z);

// ワールドの状態レスポンス (サーバー → クライアント)
[MemoryPackable]
public readonly partial record struct WorldSnapshot(TickNumber Tick, int PlayerCount);
```

> **なぜ `readonly partial record struct` にするの？**
> `class` ではなく `readonly struct`（値型）にすることで、通信のたびにヒープメモリ（GC 対象）が確保されるのを防ぎ、**アロケーション 0 バイト**でシリアライズ・デシリアライズを行えます。

### 4-2. パターン A: Minimal API 風 `MapRpc` で手軽に登録する

1〜2 個のシンプルな RPC なら、`Program.cs` に直接 `app.MapRpc` で書けます。

```csharp
// MethodId = 1 に対して、MoveCommand を受け取り WorldSnapshot を返すハンドラを登録
app.MapRpc<MoveCommand, WorldSnapshot>(
    methodId: 1,
    static (ctx, cmd) =>
    {
        // cmd.X, cmd.Y, cmd.Z を使って処理し、レスポンス構造体を返すだけ！
        return new WorldSnapshot(ctx.CurrentTick, PlayerCount: 1);
    });

// コンテキスト (ctx) が不要な場合はさらに短く書けます
app.MapRpc<MoveCommand, WorldSnapshot>(
    methodId: 2,
    static cmd => new WorldSnapshot(TickNumber.Zero, cmd.X >= 0 ? 1 : 0));
```

### 4-3. パターン B: `[HayabusaService]` + `[Rpc]` 属性で本格的なサービスを作る

メソッド数が多い場合や、**クライアント側の呼び出しクラスも自動生成させたい場合**は、`[HayabusaService]` クラスを作ります。

```csharp
using System.Threading.Tasks;
using Cysharp.Threading.Tasks;
using Hayabusa.Core.Primitives;
using Hayabusa.Rpc;

namespace MyHayabusaServer;

[HayabusaService]
public sealed partial class CalculatorRpcService
{
    // 1. 明示的に MethodId = 10 を指定した非同期 RPC (ValueTask<T>)
    [Rpc(MethodId = 10)]
    public ValueTask<WorldSnapshot> MoveAsync(MoveCommand command)
    {
        return new ValueTask<WorldSnapshot>(new WorldSnapshot(TickNumber.Zero, 1));
    }

    // 2. Cysharp UniTask<T> を使った非同期 RPC にも標準対応！
    [Rpc(MethodId = 11)]
    public UniTask<int> AddAsync(int a, int b)
    {
        return UniTask.FromResult(a + b);
    }

    // 3. MethodId を省略すると、メソッドシグネチャから決定論的な ID が自動採番されます。
    //    さらに DTO を作らずに複数の引数 (float x, float y, float z) を直接並べることも可能です！
    [Rpc]
    public int Multiply(int x, int y)
    {
        return x * y;
    }
}
```

サーバーへの登録は Web サービスと全く同じで **`app.MapService<CalculatorRpcService>()`** を呼ぶだけです！

```csharp
using HayabusaApp app = HayabusaApp.CreateBuilder(args).Build();

app.MapService<CalculatorRpcService>();

await app.RunAsync();
```

### 4-4. C# / Unity クライアントから RPC を呼び出す（TCP / HTTP / インメモリ）

`[HayabusaService]` を付けたクラス（例: `CalculatorRpcService`）をビルドすると、Source Generator が自動的に **`CalculatorRpcServiceClient`** という型安全なクライアントプロキシクラスを生成します！

クライアントからは以下の **3 通りの接続方法** でまったく同じメソッドを呼び出せます。

```csharp
using System;

using System.Threading.Tasks;

public static class ClientExample

    {
```

## 7. ステップ 5: 【ゲームサーバー編】60fps Room (Actor) とリアルタイム通信を実装する

`Hayabusa` 最大の特徴である、**「60fps の定周期ゲームループ（Tick）」** と **「ロック不要の Room（部屋）状態管理」**、そして **「MagicOnion `StreamingHub` 風のサーバー→全クライアント一斉ブロードキャスト」** を実装してみましょう。

### 5-1. なぜ `RoomActor` では `lock` が一切不要なのか？

通常の Web/RPC サーバー（ASP.NET Core や gRPC）では、同じ部屋（Room）にいるプレイヤー A とプレイヤー B の通信が別々のスレッドで同時に実行されるため、`Dictionary` やプレイヤー座標を更新するたびに `lock` や `ConcurrentDictionary` が必須になります。

一方、`Hayabusa` の **`RoomActor`** は、`RoomId` に基づいて**特定の 1 つの CPU コア専用スレッド（`CoreWorker`）にピン留め**されます。

```text
プレイヤーAの移動RPC ──┐
プレイヤーBの移動RPC ──┼──► [Core #0 専用スレッド] ──► BattleRoomService (RoomId: 1)
60fps 定周期 OnTick  ──┘     (常にこの1スレッドだけが順番に実行する！)
```

つまり、**その Room のメソッドや `OnTick` は絶対に複数スレッドから同時実行されません**。普通の `Dictionary<ConnectionId, PlayerState>` や `List<T>` をそのままフィールドに持ち、`lock` を 1 行も書かずに安全・超高速にゲームロジックを書けます。

### 5-2. サーバーからクライアントへの通知インターフェース（`[HayabusaHubReceiver]`）を定義する

まず、「サーバーからクライアントへプッシュ通知するイベント」と「クライアントからサーバーへ呼ぶ RPC」のインターフェースを定義します（クライアント・サーバー共有コードに置くと便利です）。

```csharp
using System.Threading.Tasks;
using Hayabusa.Core.Primitives;
using Hayabusa.Rpc;
using MemoryPack;

namespace MyGameServer;

// 1. 通信で使う構造体 (MemoryPackable)
[MemoryPackable]
public readonly partial record struct MoveCommand(float X, float Y, float Z);

[MemoryPackable]
public readonly partial record struct WorldSnapshot(TickNumber Tick, int PlayerCount);

// 2. サーバー → クライアントへのプッシュ通知契約 ([HayabusaHubReceiver])
//    これを定義すると、Source Generator が以下の 2 つを自動生成します:
//    ・サーバー側拡張メソッド : room.BroadcastOnWorldTick(snapshot)
//    ・クライアント側バインダ : client.BindReceiver(receiver)
[HayabusaHubReceiver]
public interface IBattleHubReceiver
{
    [Rpc(MethodId = 100)]
    void OnWorldTick(WorldSnapshot snapshot);
}

// 3. クライアント → サーバーへの RPC 契約 (MagicOnion の IStreamingHub と同じ書き方)
public interface IBattleRoomHub : IStreamingHub<IBattleRoomHub, IBattleHubReceiver>
{
    [Rpc(MethodId = 1)]
    ValueTask<WorldSnapshot> MoveAsync(MoveCommand command);
}
```

### 5-3. `RoomActor` を継承して 60fps ゲームルームを実装する

次に、`RoomActor` を継承して実際のゲームルーム `BattleRoomService` を実装します。

```csharp
using System.Collections.Generic;
using System.Threading.Tasks;
using Hayabusa.Core.Primitives;
using Hayabusa.Rpc;
using Hayabusa.Runtime.Rooms;

namespace MyGameServer;

[HayabusaService]
public sealed partial class BattleRoomService : RoomActor, IBattleRoomHub
{
    // ★同一コアの専用スレッドからしか触られないため、普通の Dictionary で完全にスレッドセーフ！
    private readonly Dictionary<ConnectionId, MoveCommand> _playerPositions = new();

    // クライアントから MoveAsync が呼ばれたときの処理
    [Rpc(MethodId = 1)]
    public ValueTask<WorldSnapshot> MoveAsync(MoveCommand command)
    {
        ConnectionId callerId = Context.ConnectionId;
        if (callerId.IsValid)
        {
            // プレイヤーをこの Room のブロードキャスト対象リストに参加させる
            JoinPlayer(callerId);

            // 座標を更新 (lock 不要！)
            _playerPositions[callerId] = command;
        }

        // 現在の Tick 番号とルーム内のプレイヤー数を返す
        return new ValueTask<WorldSnapshot>(new WorldSnapshot(CurrentTick, PlayerCount));
    }

    // ★60fps (約16.66ms周期) でワーカースレッドから自動的に呼ばれる定周期コールバック
    protected override void OnTick(TickNumber tick)
    {
        // ルーム内にいる全プレイヤーへ現在のワールド状態を一斉送信（ゼロコピー）
        var snapshot = new WorldSnapshot(tick, PlayerCount);

        // Source Generator が IBattleHubReceiver から自動生成したブロードキャスト拡張メソッド
        _ = this.BroadcastOnWorldTick(snapshot);
    }
}
```

### 5-4. サーバーに Room を登録して起動する

`Program.cs` で `app.RegisterRoom<BattleRoomService>(new RoomId(1UL))` を呼び出してルームを登録します。

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;
using Hayabusa.Core.Primitives;
using Hayabusa.Runtime.Hosting;

namespace MyGameServer;

public static class Program
{
    public static async Task Main(string[] args)
    {
        // 60fps (TickRate = 60Hz) でサーバーを構築
        using HayabusaApp app = HayabusaApp.CreateBuilder(args)
            .UseThreadPerCore(static options => options.TickRate = 60)
            .Build();

        // RoomId = 1 のバトルルームを作成・登録 (担当 CPU コアに自動ピン留めされます)
        _ = app.RegisterRoom<BattleRoomService>(new RoomId(1UL));

        // 死活監視用の HTTP エンドポイントも同時に公開可能
        app.MapGet("/health", static ctx => ctx.WriteUtf8("OK"u8));

        using var cts = new CancellationTokenSource();
        Console.CancelKeyPress += (_, e) =>
        {
            e.Cancel = true;
            cts.Cancel();
        };

        await app.RunAsync(cts.Token);
    }
}
```

### 5-5. クライアント側で RPC 送信 & 60fps ブロードキャストを受信する

クライアント側（Unity や .NET コンソールアプリ）では、`IBattleHubReceiver` を実装したクラスを作り、**`BindReceiver`** で登録するだけでサーバーからの 60fps ブロードキャストを受け取れます。

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

namespace MyGameServer;

// 1. サーバーからのプッシュ通知を受け取るクラス
public sealed class ConsoleBattleReceiver : IBattleHubReceiver
{
    public void OnWorldTick(WorldSnapshot snapshot)
    {
        Console.WriteLine($"[60fps Broadcast] Tick={snapshot.Tick.Value}, Players={snapshot.PlayerCount}");
    }
}

public static class GameClientExample
{
    public static async Task RunGameClientAsync(CancellationToken ct = default)
    {
        // 2. サーバーへ TCP 接続 (Source Generator が自動生成した BattleRoomServiceClient)
        using BattleRoomServiceClient client =
            await BattleRoomServiceClient.ConnectAsync("127.0.0.1", port: 8001, ct);

        // 3. サーバーからの通知 (IBattleHubReceiver) をバインド
        //    戻り値の IDisposable を Dispose すると購読解除されます (R3 の DisposableBag 等と相性抜群)
        var receiver = new ConsoleBattleReceiver();
        using IDisposable subscription = client.InnerClient.BindReceiver(receiver);

        // 4. サーバーへ移動コマンド (MoveAsync) を送信！
        WorldSnapshot reply = await client.MoveAsync(new MoveCommand(1.5f, 0.0f, -3.0f), ct);
        Console.WriteLine($"MoveAsync Reply: Tick={reply.Tick.Value}, Players={reply.PlayerCount}");

        // 5. サーバーから届くブロードキャストフレームを受信して receiver.OnWorldTick を発火させる
        await client.InnerClient.ReceiveBroadcastsOnceAsync(ct);
    }
}
```

## 8. ステップ 6: 【カスタムループ編】独自 ECS や物理エンジンを定周期 Tick で回す

`RoomActor` を使わず、自前の ECS（Arch / Entitas など）や Box2D / 物理エンジンのワールド更新ループを `Hayabusa` の Thread-per-Core ランタイム上で定周期実行したい場合は、**`IGameLoopTickHandler`** インターフェースを実装して `app.RegisterTickHandler(...)` で登録します。

```csharp
    {
        // 指定した TickRate (例: 60Hz) で毎フレーム呼ばれます

    }

    }
}
```

## 9. ステップ 7: 【単体テスト編】ソケット不要！インメモリで高速テストを書く

`Hayabusa` で作ったサーバーは、実際に TCP ポートを開かなくても **`app.CreateInMemoryClient()`** や **`HayabusaHybridBridge`** を使って、**メモリ上だけで数ミリ秒で単体テスト・結合テストを実行**できます。

以下は、そのままコピーして使える xUnit テストコードの例です。

```csharp
using System;
using System.Text;
using System.Threading.Tasks;

using Hayabusa.Core.Primitives;
using Hayabusa.Rpc.Client;
using Hayabusa.Runtime.Hosting;

using Xunit;

namespace MyGameServer.Tests;

public sealed class ServerIntegrationTests
{
    [Fact]
    public async Task MoveAsync_InMemoryClient_ReturnsUpdatedSnapshot()

        using HayabusaApp app = HayabusaApp.CreateBuilder()
            .UseThreadPerCore(static opts => opts.WorkerThreads = 1)
            .Build();

        _ = app.RegisterRoom<BattleRoomService>(new RoomId(1UL));

        using var client = new BattleRoomServiceClient(app.CreateInMemoryClient(), ownsClient: true);

        WorldSnapshot response = await client.MoveAsync(new MoveCommand(10f, 20f, 30f));
```

## 10. ステップ 8: 環境変数・CLI 引数と本番デプロイ（NativeAOT / Docker）

### 8-1. サーバーロールの切り替え（Web 単体 / ゲーム単体 / 両方）

`Hayabusa` は、コードを 1 行も書き換えることなく、起動時の引数や環境変数だけで **3 つのサーバー形態（Role）** を切り替えられます。もちろん、コード上で明示的に固定することも可能です。

| ロール | コードでの指定方法 | CLI 引数 | 環境変数 `HAYABUSA_ROLE` | 動作内容 |
| --- | --- | --- | --- | --- |
| **Web + ゲーム両方**（デフォルト） | `.UseWebAndGameServer()` | `--web-and-game` | `both` | HTTP エンドポイントとバイナリ RPC / 60fps Room Tick の両方を単一ランタイムで処理 |
| **Web サーバー単体** | `.UseWebServerOnly()` | `--web-only` | `web` | ゲーム Tick ループとバイナリ RPC を停止し、100% ステートレス HTTP 処理に専念 |
| **ゲームサーバー単体** | `.UseGameServerOnly()` | `--game-only` | `game` | HTTP パーサを停止し、MemoryPack バイナリ RPC と定周期 Room Tick に 100% 専念 |

### 8-2. 環境変数・CLI オプション一覧表

`HayabusaApp.CreateBuilder(args)` が自動で読み取るすべての設定項目です（優先順位は **コード内の明示上書き ＞ CLI 引数 ＞ 環境変数 ＞ デフォルト値** です）。

| 環境変数 | CLI 引数 | デフォルト値 | 説明 |
| --- | --- | --- | --- |
| `HAYABUSA_ROLE` | `--role` (`--web-only` / `--game-only` / `--web-and-game`) | `both` | サーバーの動作ロール（`web`, `game`, `both`） |
| `HAYABUSA_BIND_ADDRESS` | `--bind` | `0.0.0.0` | 待ち受けバインド IP アドレス（ローカルのみなら `127.0.0.1`） |
| `HAYABUSA_HTTP_PORT` | `--http-port` | `8000` (※1) | HTTP / Minimal API 待ち受けポート |
| `HAYABUSA_RPC_PORT` | `--rpc-port` | `8001` (※1) | MemoryPack バイナリ RPC / Room 待ち受けポート |
| `HAYABUSA_WORKER_THREADS` | `--workers` | `0` | Thread-per-Core スレッド数（`0` で CPU 論理コア数を自動検出） |
| `HAYABUSA_TICK_RATE` | `--tick-rate` | `60` | Room / ゲームループの 1 秒あたり Tick 回数（Hz: `60` = 60fps、`30` = 30fps） |
| `HAYABUSA_TRANSPORT` | `--transport` | `auto` | `auto`（Linux では `io_uring` を優先し、非対応環境では `socket` に自動フォールバック）、`io_uring`、`socket` |

> ※1: `.env.example` では `8000` / `8001`、環境変数未設定時のクラス規定値は `5000` / `5001` です。本番やローカル起動時は `--http-port 8000 --rpc-port 8001` または `.env` で明示指定することを推奨します。

### 8-3. NativeAOT シングルバイナリのビルドと Docker デプロイ

`Hayabusa` は動的リフレクションを一切使わないため、**.NET NativeAOT** によって「.NET ランタイム不要で動くネイティブ機械語の単一実行ファイル」にコンパイルできます。起動時間が数ミリ秒になり、メモリ消費量も最小化されます。

## 11. ステップ 9: よくある質問・つまずきポイントと解決策（FAQ）

実装中に困ったときは、まずここを確認してください。

### Q1. `[HayabusaService]` や `[MemoryPackable]` を付けたのにメソッドやクライアントクラスが生成されません / コンパイルエラーになります

**A. クラスや構造体に `partial` キーワードが付いているか確認してください。**
C# の Source Generator は、あなたが書いたクラスや構造体の「別ファイル（`*.g.cs`）」としてコードを自動追加します。そのため、`partial` が抜けているとコードを追加できません。

- **NG**: `public sealed class BattleRoomService : RoomActor`
- **OK**: `public sealed partial class BattleRoomService : RoomActor`
- **NG**: `public readonly record struct MoveCommand(float X, float Y, float Z);`
- **OK**: `public readonly partial record struct MoveCommand(float X, float Y, float Z);`

また、`Hayabusa.Generator` は間違いを見つけやすくするため、以下のコンパイル時診断エラー（`HAYABUSA001`〜`005`）を出力します。

| 診断 ID | 原因と解決策 |
| --- | --- |
| `HAYABUSA001` | `[HayabusaService]` を付けたクラスに **`partial` が付いていません**。`partial class` に修正してください。 |
| `HAYABUSA002` | `[Rpc]` メソッドの戻り値型が非対応です。`void`, `T`, `ValueTask`, `ValueTask<T>`, `UniTask`, `UniTask<T>` のいずれかにしてください（標準の `Task` はアロケーション防止のため禁止されています）。 |
| `HAYABUSA003` | 同じクラス内で **`[Rpc(MethodId = ...)]` の番号が重複**しています。別の番号にするか、`[Rpc]`（自動採番）にしてください。 |
| `HAYABUSA004` | `[Get]` / `[Post]` のパス文字列が `/` で始まっていません（例: `"/health"` のように先頭に `/` を付けてください）。 |
| `HAYABUSA005` | `[HayabusaHubReceiver]` は `interface` にのみ付与できます。また、その中のメソッドの戻り値は `void` にしてください。 |

### Q2. Windows や macOS、あるいは古い Linux カーネルでもそのまま動きますか？

**A. はい、コード変更なしでそのまま動きます。**
デフォルトの `HAYABUSA_TRANSPORT=auto` では、Linux かつ `io_uring` が利用可能な環境では `IoUringTransport` を使用し、Windows / macOS や `io_uring` が制限されたコンテナ環境では**自動的に `SocketEventTransport`（Windows IOCP / epoll 対応）へフォールバック**します。クラッシュすることは一切ありません。

### Q3. 既存の ASP.NET Core (Kestrel) や Blazor Server プロジェクトの中に組み込めますか？

**A. はい、`HayabusaHybridBridge` を使ってインプロセスでそのまま統合できます。**
Kestrel の WebSocket や HTTP エンドポイントで受け取ったバイト列を `HayabusaHybridBridge.DispatchRawRpcFrameAsync(...)` に渡すだけで、ソケット通信を介さずに同一プロセス内の `HayabusaApp`（`RoomActor` や RPC サービス）をゼロオーバーヘッドで呼び出せます。
