# Source Generator 設計・実装規約（Source Generator Architecture）

`hayabusa` がリフレクションと実行時オーバーヘッドを完全に排除し、NativeAOT に 100% 対応するための心臓部が **`Hayabusa.Generator`** です。IDE（Cursor / Visual Studio / Rider）の入力応答性を損なわないよう、Roslyn の **`IIncrementalGenerator`** ベストプラクティスを厳守します。

## 1. `IIncrementalGenerator` の絶対ルール（IDE 性能保護）

1. **`ISourceGenerator`（旧 API）は使用禁止**:
   - 必ず `IIncrementalGenerator` を実装する。
2. **`ForAttributeWithMetadataName` を使用する**:
   - 全構文木を走査する `CreateSyntaxProvider` ではなく、必ず `context.SyntaxProvider.ForAttributeWithMetadataName("Hayabusa.Rpc.HayabusaServiceAttribute", ...)` を使用して Roslyn の高速インデックスを活用する。
3. **パイプラインの中間モデルに `ISymbol` や `SyntaxNode` を保持しない**:
   - `ISymbol` や `SyntaxNode` はコンパイルごとに再生成されるため、パイプラインモデルに含めるとインクリメンタルキャッシュが毎回ミスし、キータイプごとに全コード再生成が走ってしまう。
   - `transform` ステップ内で必ず **`IEquatable<T>` を実装した独自の不変 `readonly record struct` または `EquatableArray<T>` モデル** に変換してから後続パイプラインへ流す。

## 2. 生成するコードの品質基準

生成される `*.g.cs` ファイルは以下の基準を満たす必要があります。

1. **ヘッダーとディレクティブ**:
   ```csharp
   // <auto-generated />
   #nullable enable
   #pragma warning disable CS1591 // Missing XML comment
   ```
2. **完全修飾名（`global::`）の徹底**:
   - ユーザーコード側の名前空間衝突を防ぐため、生成コード内のすべての型参照には `global::System.ReadOnlySpan<byte>` や `global::MemoryPack.MemoryPackSerializer` のように **`global::`** プレフィックスを付与する。
3. **分岐最適化されたディスパッチャ生成とコンパクト RPC 記法**:
   - **RPC ディスパッチ**: `MethodId`（`int`）に対するフラットな `switch` 文を生成し、該当メソッドで `MemoryPackSerializer.Deserialize<TRequest>(payloadSpan)` → サービスメソッド呼び出し → `MemoryPackSerializer.Serialize(ref responseWriter, in result)` をインライン展開する。
   - **コンパクト RPC 記法の自動変換**:
     - `MethodId` 省略時の自動採番（`MethodId.FromRoute(serviceName, methodName)` と同一の 31-bit 正整数 FNV-1a ハッシュ）
     - 2個以上の引数を持つ `[Rpc]` メソッドの自動 `ValueTuple` シリアライズ／デシリアライズ展開（専用 Request DTO の定義不要）
     - `ValueTask<T>` / `UniTask<T>` に加え、同期戻り値 `T` および `void` の直接サポート
     - `<ServiceName>Client` へのゼロアロケーション `Write*Request` と非同期呼び出しメソッド（`ConnectAsync` / `CreateInMemory` / `*Async`）の両方の自動生成
   - **HTTP ルーティング**: パス文字列を毎回比較するのではなく、パス長と先頭 4/8 バイト整数比較（`BinaryPrimitives.ReadUInt32LittleEndian` 等）を組み合わせた **コンパイル時 Radix Trie（基数木）** を C# コードとして出力する。

## 3. 診断エラー（Diagnostics）の設計

不正なサービス定義に対しては、実行時エラーではなくコンパイル時に分かりやすい Roslyn Diagnostic を出力します。

| ID | 重要度 | 内容 |
| --- | --- | --- |
| `HAYABUSA001` | Error | `[HayabusaService]` を付与した型が `partial` ではない、または対象インターフェースが不正 |
| `HAYABUSA002` | Error |同一サービス内で `[Rpc(methodId)]` の `MethodId` が重複している |
| `HAYABUSA003` | Error | RPC の引数または戻り値の型に `[MemoryPackable]`（またはプリミティブ互換）が付与されていない |
| `HAYABUSA004` | Error | 非同期 RPC メソッドの戻り値が `ValueTask` / `ValueTask<T>` / `UniTask` 以外（`Task` や `async void`）になっている |
| `HAYABUSA005` | Error | HTTP ルートテンプレート（例: `[Get("/users/{id}")]`）の構文またはバインド対象パラメータ名が一致しない |
